 #### DataStore persistence guidelines
 
 Because `syncToDataStore` serializes and writes to disk whenever a
 `PersistToDataStore` key's value changes, follow these guidelines when choosing
 what and when to persist:
 
-* **Save start or end timestamps instead of every timer tick**: For timers or
-  playback progress, persist a stable reference value (such as `endTimeMillis`
-  or `startedAtMillis`) rather than updating a `PersistToDataStore` key every
-  second or frame, and compute the live elapsed or remaining display in the UI.
-* **Debounce rapid user input before updating a persisted key**: For text
-  drafts, search queries, or sliders, hold the immediate input in an in-memory
-  `MutableState` (or a `StateStoreKey` that doesn't implement
-  `PersistToDataStore`) and only call `setState` on the persisted
-  `StateStoreKey` after the input settles.
-* **Keep persisted keys lightweight**: All `PersistToDataStore` keys in a
-  `StateStore` are serialized together into a single file on each update.
-  Persist compact session state—such as active IDs, filter selections, or
-  in-progress form drafts—and keep large collections or queryable datasets in
-  [Room](/training/data-storage/room).
